# Library connector v0

A local, read-only MCP server that lets your Claude read one newsletters Library.
Branch `connector-v0`. Not merged. Code: `mcp/library/`. Tests: `tests/test_library_connector.py`.

## What it is

Three tools, all read-only:

| Tool | Returns |
|---|---|
| `list_editions` | every Published edition (slug, ref, type, title, issue, date) and how many were withheld because they are not Published |
| `read_edition(slug)` | one Published edition as plain text |
| `search_library(query, limit=10)` | Published editions containing every word of the query, ranked by hits, with a snippet |

It reads the folder the engine already writes (`ids.json` + `site/<slug>.html`). It never writes,
never calls the network, and never serves a Draft or In Review edition. If asked for one, it says
so and gives the reason.

**Which Library.** There is no Pulse IQ Library in this repo yet. The steps below point at
`content/rev1`, the engine's own sample Library (real engine output, not client data). The tests
use a small fixture Library at `tests/fixtures/library-fixture/`, labelled FIXTURE. When Pulse IQ
has a Library folder of the same shape, change the `--library` path. Nothing else changes.

## Set it up (once, about five minutes)

You need Python 3.10 or newer. Run these in a terminal.

```bash
# 1. Get the branch
git clone https://github.com/johnair01/newsletters.git ~/newsletters
cd ~/newsletters && git checkout connector-v0

# 2. A small virtual environment that has only the MCP SDK (works with mcp 1.x or 2.x)
python3 -m venv ~/.venvs/newsletters-library
~/.venvs/newsletters-library/bin/pip install mcp

# 3. Check it starts (Ctrl-C to stop; silence means it is waiting for Claude, which is right)
~/.venvs/newsletters-library/bin/python ~/newsletters/mcp/library/server.py --library ~/newsletters/content/rev1
```

If you already have a clone, skip the clone and just `git fetch && git checkout connector-v0`.
Use absolute paths below. Replace `/Users/YOU` with your home folder (`echo $HOME` prints it).

### Claude Code

```bash
claude mcp add newsletters-library -- \
  /Users/YOU/.venvs/newsletters-library/bin/python \
  /Users/YOU/newsletters/mcp/library/server.py \
  --library /Users/YOU/newsletters/content/rev1
```

Then start `claude`, type `/mcp`, and check that `newsletters-library` shows as connected with 3 tools.
To remove it later: `claude mcp remove newsletters-library`.

### Claude Desktop

Open Settings, Developer, Edit Config. That opens `claude_desktop_config.json`
(macOS: `~/Library/Application Support/Claude/`, Windows: `%APPDATA%\Claude\`). Add this, keeping
any servers you already have inside `mcpServers`:

```json
{
  "mcpServers": {
    "newsletters-library": {
      "command": "/Users/YOU/.venvs/newsletters-library/bin/python",
      "args": [
        "/Users/YOU/newsletters/mcp/library/server.py",
        "--library",
        "/Users/YOU/newsletters/content/rev1"
      ]
    }
  }
}
```

Quit Claude Desktop fully and reopen it. The tools menu in a new chat should list
`newsletters-library` with 3 tools. Desktop does not use your shell PATH, so the full path to the
venv's `python` is required.

## Ask it three questions

1. **"What editions are in my Library?"**
   Expect: it calls `list_editions` and names 6 published editions (3 audience cuts of the weekly
   newsletter, the kickoff and data-model reports, Episode 01 of the show), and says 4 more are
   withheld because they are not published.
2. **"Read me the kickoff report and tell me what it decided."**
   Expect: it calls `read_edition` with `report-kickoff` and summarises it, naming the report.
3. **"Where does my Library talk about the review gate? Quote it."**
   Expect: it calls `search_library`, then likely `read_edition` on the top hits, and quotes them.

Optional honesty check: **"Read me the plan report (report-plan)."** It should refuse and say the
edition is In Review, not published. That is the review gate holding.

## Known limits

- The three newsletter editions share one title (they are audience cuts). Claude tells them apart
  by slug.
- Text comes from the rendered page, so it includes small labels like "The Report Published" and
  the byline. Claims and traces are not exposed as structure yet.
- Out on purpose: writes, unpublished editions, more than one Library, hosting, auth.
