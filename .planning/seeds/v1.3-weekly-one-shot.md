# Seed — Milestone v1.3: The Weekly, One Shot

**Place at:** `.planning/seeds/v1.3-weekly-one-shot.md`

## Intent

A recurring **module weekly** — the deck an engineering module ships every week — becomes a product output: existing adapters populate Sources, a weekly composer builds one `Surface(REPORT, Draft)`, a new PPTX renderer emits the deck through the review gate. Same spine, one new output format, a few new block kinds. The author writes the story; the engine makes it publishable, traced, and repeatable.

## Current state (verify against the live repo before building on it)

- **Extraction exists.** DistillPort backends: ADAPT-02 `.eml`, ADAPT-03 `.xlsx`, ADAPT-04 `.pptx`, ADAPT-05 Power BI PBIP (TMDL + PBIR) — each minting `Source → Claim(+Trace)` via shared `normalize()`.
- **Module composition exists.** `swimlane.py` + `compose.py` produce a per-module `Surface(REPORT, Draft)` (KpiStripBlock + ClaimsBlock, honest `missing[]`); the `content/module` corpus is live on the published site.
- **Authored-voice path exists.** Case Spec (`casespec.py`, `docs/case-spec.md`): hand-authored YAML lifted through the zero-AI spine; author's text carried byte-verbatim with real-span Traces; absences disclosed; `config:` values bound but never minted into claims.
- **One publish channel exists** (v1.2): assemble → gate-checked deploy from `main` only; enforced gate set per `.planning/ROADMAP.md`.

## The gap — what this milestone builds

1. **PPTX as an output.** Surfaces render to HTML only; python-pptx appears only on the loader path. No deck writer exists.
2. **Weekly block kinds.** The module report carries KPI strips + claims; a weekly also needs authored narrative (highlights/lowlights), recognitions, a team block, and photo/screenshot blocks.
3. **An asset evidence path.** Transcripts are text; images currently have no traced route into a Surface.
4. **BI data values.** ADAPT-05 reads the report *definition* (model, measures, visual metadata), not current values.

## Requirements

**WKLY-01 — PPTX Surface renderer.**
Deterministic renderer: composed weekly Surface → `.pptx`.
- python-pptx stays behind the `[pptx]` extra (writer and loader share it); core spine untouched; bare-install CI stays green.
- **Determinism gate extends to `.pptx`.** A deck is a zip; zips embed timestamps and part ordering. Prove byte-stable double-render (fixed epoch per the existing `EPOCH_ZERO` pattern, sorted parts, stable rels) — or, if the writer cannot be made byte-stable, record a content-stable definition (unzipped parts byte-identical under normalized zip metadata) as a Specify-phase decision with evidence. Decided up front, not discovered in Validate.
- Every rendered deck carries the generated-by marker in a durable field (core properties or notes — mechanism decided in Specify) and renders visibly **Draft-watermarked** until the Surface is Published. The gate itself is untouched.
- **Template as layout contract.** The renderer fills placeholders in an operator-supplied template `.pptx`; it never invents layout. The repo ships a minimal synthetic template for the sample corpus and CI.

**WKLY-02 — Weekly composition + authored spec.**
New block kinds: `NarrativeBlock` (authored highlights/lowlights), `RecognitionsBlock`, `TeamBlock` (name, role, short lines, photo ref), `AssetBlock` — alongside the existing per-lane KPI strip + claims. Authored material arrives as a **Weekly Spec** YAML on the Case Spec mechanism: file text is the evidence, narrative carried byte-verbatim as the author's voice, absences → `missing[]`, org-specific `config:` bound but never claimed. Faithful, not suggestive: the composer assembles and traces; it never editorializes.

**WKLY-03 — Asset evidence path.**
An asset (photo, screenshot) is a content-addressed file with required provenance (origin + optional deep link). It enters a Surface only via an `AssetBlock` tracing to that record. An asset without provenance routes to `missing[]` — shown to the reviewer, never placed silently.

**WKLY-04 — BI values, the cheap way.**
Values arrive as **exported `.xlsx`/`.csv` fed to ADAPT-03** — no new adapter. Where export is unavailable, a screenshot-with-deep-link enters via WKLY-03. ADAPT-05 remains the definition-side reader; out of scope to extend it this milestone.

**WKLY-05 — Sample weekly corpus, in CI.**
A synthetic weekly in the `content/module` lineage (fabricated everything; honesty-path coverage: a lane with no KPIs, a recognition with no source email, an asset with no provenance) composed and rendered to `.pptx` under the carried gate set: pytest · lint-imports · `newsletters check` over all corpora · double-render stability (including the new `.pptx` per WKLY-01's recorded definition) · bare-install untouched · mypy/black/isort no-new-failures.

**WKLY-06 — Operator recipe.**
`docs/weekly.md`: how an operator points the adapters at a real workbook / template deck / `.eml` drop / photo folder (read-only, data stays local — the WORK-01 pattern), authors the Weekly Spec, runs compose + render, and reviews. The bar: executable by an operator who isn't the author.

## Phases

## Hard-rule check

No auto-publish (deck ships Draft, watermarked; gate untouched) · every claim traces / `missing[]` disclosed · AI-optional core (renderer is deterministic code behind `[pptx]`; zero AI in the path) · faithful-not-suggestive (narrative is authored; composer never editorializes) · branch + PR only; atomic commits; compass + RETRO per phase · proprietary stripped, personal preserved (synthetic sample; operator data never committed).

## Open questions (resolve in Phase 1)

1. Surface kind: reuse `REPORT` with a `.pptx` renderer (recommended — smallest change) vs. a new kind.
2. Asset provenance minimum: folder + date + event label, or per-asset link required?
3. Template contract shape: named placeholders vs. positional layout mapping.
