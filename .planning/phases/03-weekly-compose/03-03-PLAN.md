**Discretion exercised here, and why (log verbatim in the SUMMARY):**
- **The asset record lives in the weekly document, not in a separate record file.** `Source.transcript`
  is a `str` and `Source.content_hash()` hashes that string, so a binary can never be a `Source`.
  The `assets:` subtree *is* the record and the spec file is its `Source`; the `sha256` hex is a
  literal substring of that file and traces verbatim like any other field. One Source, one hash,
  one containment check. A later phase wanting standalone record files uses the same machinery with
  a second `Source`; nothing here forecloses it.
- **`compose._addressed` is promoted to a public `compose.addressed`** and imported by the weekly
  composer rather than copied. It is the trust predicate ("traced AND every trace content-addressed");
  two copies of a trust predicate drift exactly as two normalizers do. No test references the
  private name (verified against the live repo), and `compose_module_report`'s 20+ existing tests
  police the rename.
- **Surface identity:** `title = spec.week` and `eyebrow = spec.module`, each carried **verbatim,
  never joined** — a join would be composer-authored connective text. Absent values fall back to the
  Case Spec's stem-derived title / the constant `"Report · weekly"` respectively, with the absence
  already disclosed by the loader.
- **Empty sections produce no empty block.** A weekly with no lowlights gets no `NarrativeBlock`
  for lowlights; the absence is in `missing[]` where the reviewer sees it. An empty block would
  render an empty `div.block` and assert nothing. (The deck's matching behaviour is plan 03-04's.)

**Fixed block order — part of the determinism claim, asserted by test:**
`ProseBlock` (declared connective constant, numeral-free) → `KpiStripBlock`* (binding order) →
`ClaimsBlock` → `NarrativeBlock`(highlight) → `NarrativeBlock`(lowlight) → `RecognitionsBlock` →
`TeamBlock` → `AssetBlock`* (in `assets:` **file order**).

**Pitfall 8:** `Surface.model_config` sets `validate_assignment=True`. Build the blocks list first
and pass it to the constructor; never mutate `surface.blocks` afterwards.

**Ordering:** `team[].photo` resolution depends on which assets were *placed*, and `assets:` appears
after `team:` in the schema. Keep the minting pass file-ordered (03-02) and resolve references in
the second pass from already-minted data. Never re-enter the minter out of order.
