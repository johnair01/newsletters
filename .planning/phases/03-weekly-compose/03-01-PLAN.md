Binding decisions this plan implements:
- **D-01** — the weekly reuses `Surface(REPORT)`; `semantic.py`'s `kind` enum is untouched. Only the
  `Block` union grows.
- **D-02 (type-level half)** — `AssetBlock.asset` is REQUIRED and `AssetBlock.evidence` carries
  `min_length=1`, so "an asset without provenance reached a Surface" is *unrepresentable*, not
  policed by a check somebody can forget to call. Deliberate contrast: `Recognition.evidence`
  defaults to `[]` and may legitimately stay empty (weekly-spec rule 6).
- **CONTEXT decision 5** — every new kind gets an HTML branch using existing tokens, AND the
  fall-through becomes fail-loud.

Hard constraints (each proven by experiment in 03-RESEARCH — do not re-litigate):
- **ZERO new CSS.** `render._CSS` is inlined into every page; planting one rule turned
  `test_publish.py::test_committed_rev1_equals_fresh_build` and `..._work_...` red. Every class the
  four branches need already exists.
- **PURE INSERTION in `semantic.py`.** Zero deleted lines against the milestone base. The union
  members are appended after `GlossaryBlock,`; the sub-models go beside `KpiItem`/`Chapter`/
  `GlossaryTerm`.
- The old freeze test (`tests/test_compose.py::test_faithfulness_coverage_semantic_templates_site_are_untouched`)
  runs `git diff HEAD`, which compares the **working tree** to HEAD. It goes red on an uncommitted
  edit and green the moment that edit is committed — in CI's clean checkout it has never been
  capable of failing. Task 3 replaces it; a red from it *during* Task 1 is expected and is not a
  failure signal.

Base ref for every diff-shape gate in this phase (recorded decision, 03-VALIDATION Wave 0):
`git merge-base HEAD origin/main` — never `HEAD`.
